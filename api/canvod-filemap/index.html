fetch_recipe(url, *, timeout=30.0) ¶

Recipe¶

Naming recipe: user-defined mapping from arbitrary filenames to canVOD names.

A recipe is a small YAML file that describes: 1. The canonical identity of a receiver (site, agency, sampling, etc.) 2. How to extract date/time fields from the user's physical filenames.

The field extraction is a sequential left-to-right walk over the filename. Each entry in the fields list consumes characters and either extracts a named value or skips literal characters.

Recognized field names
  • year 4-digit year (e.g. 2025)
  • yy 2-digit year (80-99 → 19xx, 00-79 → 20xx)
  • doy day of year (1-366)
  • month month (01-12)
  • day day of month (01-31)
  • hour hour (00-23)
  • minute minute (00-59)
  • hour_letter RINEX 2 session letter (a-x = hours 0-23; 0 = daily file)
  • skip ignore these characters

Example recipe (YAML)

::

name: fangorn_reference
description: Orthanc, reference receiver

site: FAN
agency: INK
receiver_number: 1
receiver_type: reference
sampling: "05S"
period: "15M"
content: "AA"
file_type: rnx

glob: "*.??o"

# Example: rref001a15.25o
fields:
  - skip: 4
  - doy: 3
  - hour_letter: 1
  - minute: 2
  - skip: 1
  - yy: 2
  - skip: 1

Example recipe for exotic filenames

::

# Example: STATION_2025_042_00_15.rinex
fields:
  - skip: 8
  - year: 4
  - skip: 1
  - doy: 3
  - skip: 1
  - hour: 2
  - skip: 1
  - minute: 2
  - skip: 6

Recipe files¶

Where naming recipe files live, and creating them from the template.

Recipes are kept per site in the configuration directory::

<config dir>/recipes/<site>/<name>.yaml

<site> is the site name in the settings file and <name> the receiver's recipe: setting. Recipe files are user data: they are not part of any repository and are only read from this location.
